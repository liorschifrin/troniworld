## Diagnosis of the old importer (`upload_game_csv`)

- `if od_val not in ['O','X']: continue` and `if neither team scored: continue` silently dropped columns. The final loop then **deleted** every existing point whose index was not in `valid_point_indices`, cascading to its events and nulling its comments' `point_id`. So one typo in the O/D row deleted a point and detached its comments.
- Both scores in one column were accepted (Tron won silently); player cells were accepted with any text, so `3/4` or `//` counted as a plain participant and lost their injury meaning; a duplicate player row was silently ignored; a nameless row was skipped.
- The roster was cleared and rebuilt, and every point's players were cleared and re-added, even when nothing changed.
- All of this ran as one request: no preview, no version check, a second admin's edits in between were overwritten without notice.

## Decisions

1. **Two steps.** `POST upload_csv` parses and previews (200) or reports errors (400); it never writes. `POST upload_csv/apply` re-parses the CSV carried in a hidden field (so a forged body hits the same validator), then applies. The preview page is `upload_game_csv_preview.html`.
2. **Strict validation.** Errors (each with row and column, up to 100 shown with the total): missing or invalid O/D; both or neither score row filled; an empty column between other points; injury cells that contain `/` but are not exactly `N/` or `/N`; duplicate or nameless player rows; names over 100 characters; non-UTF-8; fewer than 4 rows; no points at all; file over 1 MB, 1000 rows or 500 columns. Trailing empty columns (spreadsheet padding), a UTF-8 BOM and CRLF are accepted. Non-slash player cells remain "any non-blank value" as before.
3. **Hide, not delete.** New column `points.hidden_by_import` (migration `n9o0p1q2r3s4`, additive, NOT NULL, default 0). Hidden points keep id, comments, annotations and player links. All display and statistics reads go through `Game.visible_points`/`hidden_by_import` filters (game page, my games, team data, option lists); point PATCH, comment creation and player-sheet edits on a hidden point return 404; clear-player-sheet skips them. A CSV that contains a hidden point's index restores it (listed as "restored"); the upload page lists hidden points with a Restore button. Applying an import that hides points needs a confirmation checkbox (`confirm_hidden`).
4. **Version marker = content hash, not a counter.** `state_token` is SHA-256 over every point (id, index, offense/result, hidden flag, players, injury subs, film time, no-film flag, labels), the roster, `player_order_data`, and which CSV players already exist. A counter (`game.revision`) would need bumping in every one of ~8 write paths and a bigger migration; a hash covers every present and future edit path automatically. Comment changes are deliberately not part of it (import never writes comments). The check runs after taking the write lock (`UPDATE games SET id=id`, then `expire_all`), in the same transaction as the writes.
5. **Minimal writes.** Apply only reassigns a point's players or injury subs when they differ, so an identical reimport leaves every table byte-for-byte unchanged (tested).
6. **Injury subs from the CSV are authoritative** for retained points: removing the notation from the CSV clears the sub, shown in the preview as a change.

## Upgrade path

Back up, then `flask db upgrade` (head `n9o0p1q2r3s4`, from `m8n9o0p1q2r3`). It adds one column with default 0; no data rewrite, every point stays visible. Downgrade refuses while any point is hidden (restore them first). New empty databases: `flask bootstrap-db` as before.

## Limitations

SQLite write lock only (other engines would need row locks); a true two-writer race is not tested. The preview holds the CSV in a form field (re-validated at apply). Comments are not versioned, so a comment added between preview and apply is not blocked, and is never overwritten. Players named in the sheet but never marked on a point still get no `Player` row, as before. Interior empty columns are now errors (the old importer silently skipped and deleted that point); admins with sheets that rely on gaps must delete the empty column.
