## `claude-rewrite` evaluation

`claude-rewrite` has no merge base with this branch (unrelated history, so `git diff` against it is meaningless). Its tree is an earlier shape of the app: routes split into `film_api.py` (792 lines), `film_views.py` (979 lines) and `film_helpers.py` (an 11-line `fmt_dt_est`), blueprints removed, and `game_player.html` cut into partials under `templates/film_room/partials/game_player/` (`_styles`, `_comments_sidebar`, `_js_*`). It predates T03–T10 (no visibility module, CSRF, importer, watch events, hidden points), so its route files would reintroduce the pre-T03 rules. **Nothing was ported as code.** Two ideas were reused and rebuilt on the current files: the partial-per-section split of the player template (this branch's partial names are new, cut at the current section boundaries) and a shared `fmt_dt_est` (now in `serializers.py`). Its tests (`test_film_api.py`, `test_film_views.py`) assume the removed blueprint layout.

## Decisions

1. **One boundary per commit**, each behaviour-preserving and each checked by rendering the affected pages before and after on the same synthetic dataset and comparing bytes (a throwaway comparison, not committed; only row creation times differed). Rollback is `git revert` of one commit.
2. **Serializers** (`serializers.py`): the four copies of the `private_to` decoding and the date formatting in the comment routes, `my_games` and the reports use one implementation. The response keys of the thread listing, reply, create and update shapes are unchanged and pinned in `test_serializers.py`. `my_games` used to `json.loads` without a guard, so a malformed stored `private_to` crashed that page; it now decodes to `[]` like the other routes. The same decoder now also returns `[]` for stored JSON that is not a list (it used to pass a scalar or object through to the client), matching `visibility.py`, which treats such a value as author-only.
3. **Batching without moving rules**: `get_comments` still calls `can_view_comment` for every comment and reply (the audience rule is not copied); it only loads replies with one `IN` query and author roles with one query. `game_stats.py` and `player_sheet.py` always read through `hidden_by_import = False` filters and take the viewer's visible games from `visible_games_query`, as before.
4. **Template split** is a pure cut: the shell includes partials in the original order, all `_js_*` partials remain one inline script and share globals, so `let`/`const` ordering is unchanged. Rendered output of the game page is byte-identical.
5. **Static modules** only for code with no DOM or page state (`format.js`, `scoreboard.js`). They are classic scripts loaded before the inline script, so no call site changed. Modules that touch page state (comments, mentions, sheet edit, video) stay in partials; turning them into real modules needs a state contract and a browser check, which this environment cannot give.
6. **Pagination deferred**: the comment thread, notifications, analytics lists and games list all return full lists to clients that render all of them; paging any of them changes the contract.
