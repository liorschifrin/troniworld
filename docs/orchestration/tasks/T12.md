## Harness (no server, no network)

`tests/browser_support.py` installs a Playwright route on the browser context. A request to the fake origin `http://troniworld.test` is forwarded to Flask's test client (the in-memory synthetic database, same thread, no socket) and the response is fulfilled to the browser; `https://www.youtube.com/iframe_api` is answered with a local stub of the player API (it records `window.__yt.calls`, keeps a fake clock, and reports an embed error for a video id starting with `err`); every other host is refused (only the Google Fonts stylesheet tries). The stub can also fail the script (`blocked`) or never answer (`hang`). Tests build their data from the shared `records` fixture plus a few players, points and one unread mention notification. Opt-in: `tests/conftest.py` skips `browser` tests unless `-m` names the marker, and the Chromium fixture skips with a reason if the browser cannot start.

Why not run a WSGI server in a thread: the rule is that no Flask server is started, and an in-memory SQLite database would also need a shared connection across threads.

## Decisions

1. **One shortcut handler.** Two `document` `keydown` handlers (`_js_video.html` and `_js_bootstrap.html`) both handled `k`, `j`, `l` and `f`, so each press ran twice (a `k` could play then pause, `j` seeked twice, `f` requested then exited fullscreen). They are merged into one in `_js_video.html`, with the union of keys (Space, arrows, `,` `.` from the old bootstrap handler). The page also stops treating Space as play/pause when the focus is on a button, link or `role="button"` element, so Space on a focused control now activates that control. The editable-text guard now also covers `<select>` and `role="textbox"`/`combobox`/`searchbox`/`listbox`.
2. **Toggle semantics.** Mute, theater, the speed presets, watched and the private toggles carry `aria-pressed` and keep a stable name (the mute button's visible label no longer flips between "Mute" and "Unmute"; its icon and `aria-pressed` carry the state). Play/pause keeps an action name ("Play"/"Pause") and no `aria-pressed`. Disclosures carry `aria-expanded` (player sheet, `+ Comment`, notification bell, add-time menu, mobile menu).
3. **Non-button clickables** get `role="button"`, `tabindex="0"`, an `aria-label`, and Enter/Space activation from one generic handler in `_js_bootstrap.html`: the point number on timed cards (kept in step with `data-timestamp` by a small `MutationObserver`, because admin tools add and remove timestamps live), comment timestamps, admin `+ Time`/delete/reset controls and the add-time menu items. Native `<button>`s were not touched. The point card itself stays a `div` (it contains admin controls, so making it a button would nest interactive elements).
4. **Roster edit**: in edit mode each editable cell is `role="button"` with `aria-pressed` and a label ("Player, point N: on the point / subbed off / subbed on / not on the point"); one tab stop with a roving `tabindex` and arrow keys; the leave-edit actions restore the markup and return focus to **Edit Roster**. The old edit cycle is unchanged.
5. **Notifications**: bell has `aria-haspopup`, `aria-expanded`, `aria-controls` and a label with the unread count (the badge is decorative); the dropdown is a labelled dialog that receives focus on open; items are `role="button"` with a full label ("Unread @mention from X in Game: …"); tabs are `role="tab"` with `aria-selected`; Escape closes and returns focus to the bell. The 60 s refresh keeps the focused item. Nothing about what is created, read or counted changed.
6. **Mobile menu** is a labelled dialog, `inert` while closed (it was only translated off screen, so its links were in the tab order), focus moves in on open and back to the menu button on close, Escape closes.
7. **YouTube failure** is shown in a `role="alert"` box above the player and the player controls are disabled: script blocked or errored, no answer within 10 s, a player `onError` (invalid link, not embeddable, removed/private; with an "Open it on YouTube" link) and Load Video without the API.
8. **Hover-only controls** (reply buttons, reply edit/delete) are also shown on keyboard focus and on touch (`hover: none`); they were invisible and unclickable for keyboard and touch users. Mobile control buttons are at least 36 px (they were about 29 px).
9. **Focus ring**: one global `:focus-visible` outline in `film_base.html` (inputs that already draw a focus border keep it).
10. **Changes outside the task's own area, with the reason**: `tests/test_handler_escaping.py` (T04) — its `renderMentionDropdown` stub element gained two no-op methods because the renderer now sets ARIA attributes. `film_base.html` is shared by every film page, so the new focus ring, bell and menu behaviour apply on all of them. No Python code, route, model, migration, or CSRF/visibility/notification/watch-time/import logic changed. The notification fetches were not touched (a `keepalive` flag was considered and not needed: the "mark read" test passes because the request is sent before navigation).

## Results

Pre-change comparison, same tests, same harness, templates at `f6acdff`: before the fixes the browser suite was **27 failed, 9 passed** (the first full run). Examples confirmed against the old templates: `k`/`l`/`m` sequence logged `play, pause, play, …` and `seek:20` for one `l` (double handlers); Space on the focused Theater button did not toggle it; the comment box had no accessible name; no toggle had `aria-pressed`/`aria-expanded`; with the YouTube script blocked there was no message. The 9 that passed before included mark-notification-read, mark-all-read, the private-user and video-link fields not being hijacked and the mobile no-sideways-scroll check, so the old editable-text guard for input/textarea/contenteditable already held. The closed mobile menu being in the tab order was read from the CSS (it is only translated off screen) and was not reproduced before the fix.

After: `python -m pytest -m browser` → **38 passed** (about 8 s; the first run before the fixes took 6 minutes because of 30 s timeouts). Mutation checks: removing the editable guard fails 4 shortcut cases.
