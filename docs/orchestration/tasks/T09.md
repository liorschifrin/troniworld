## Findings before the change

The first request of a page load had no `session_id`, so two requests in flight at once each created a session; a retried request was counted again.

- `/film/data`: team totals and `total_games` used the selected games, but each player's `games_played` used all visible games (`visible_ids`), so a filtered page mixed populations.

## Decisions

1. **Contract v2, versioned by shape.** A chunk is `{client_session_id, event_id, seconds_watched, playback_position}`. `client_session_id` is a random id per page load (so one session per tab per load); `event_id` is unique per chunk (`<session>:<n>`). Seconds above 0 require an `event_id`; a position-only update needs only the session id. Bodies without the ids (older cached pages) get a JSON 400 and nothing is written. The integer `session_id` field is ignored, so another user's row id cannot be targeted. Chosen over a monotonic sequence because an out-of-order delayed chunk would be rejected by a "last sequence" rule and its time lost.
2. **Schema, additive (`m8n9o0p1q2r3`).** `video_watch_sessions.client_session_id` (nullable, unique with user and game) and table `video_watch_events` (`session_id`, `event_id`, `seconds_credited`, `received_at`; unique `(session_id, event_id)`). Old rows keep NULL and are never extended, so prior totals are preserved. Downgrade refuses while event rows exist, because dropping them would let a retried chunk count twice; with none, it reverses cleanly. The session total is `round(sum(seconds_credited))`, so fractional chunks are not rounded one by one.
3. **Bounds.** One event is capped at 60 s (the client sends about every 10 s). A session cannot hold more than its age plus one chunk, which stops a flood of maximum-size chunks. Negative, non-finite, boolean, and string durations, bad ids (1-64 printable characters), and positions outside 0-86400 are 400.
4. **Tabs (user decision).** Client: count only when `state === PLAYING` and `document.visibilityState === 'visible' && document.hasFocus()`; flush on pause, blur, hide, `pagehide`, `beforeunload`. Server backstop: a chunk is trimmed by the time already credited to a different session of the same user and game (`received_at` of the latest other-session event versus the chunk's window). Consecutive chunks of one session are never trimmed, so arrival jitter cannot cost time. This is an approximation: it assumes a chunk ends when it is received.
5. **Client retries.** An unacknowledged chunk is resent unchanged (same event id) on the next tick; a 2xx or 4xx response drops it, network errors and 5xx keep it (at most 50 queued). The unload path sends each pending chunk as a JSON-typed Blob; `pagehide` and `beforeunload` may both fire, which is harmless.
6. **The server parses the body as JSON whatever its media type**, so a `text/plain` beacon from a cached older page returns 200 or 400 instead of 500.
7. **Unread count** is a separate query over all unread rows for the recipient, filtered with `can_view_comment`, so it matches what the list would show without the 50-row page limit. The list is still the newest 50 (list pagination is not changed).
8. **Statistics.** `games_played` per player now uses `selected_id_set`, the same visible, filtered games as `total_games` and the point totals.
9. **CI.** `pytest -m known_failure` selects nothing now and exits 5; the workflow step accepts exit code 5 so future defects can reuse the marker.

## Limitations

- Watch time is still reported by the client. The bounds stop inflation per chunk and per session age, but a scripted client can reach "session age" of credit; this measures engagement, not proof of attention or learning.
- Cross-tab overlap trimming uses server receive time as the chunk end; a chunk delayed in transit shifts its window. No browser or YouTube player ran, so the focus/visibility gate and the unload flush are verified by source assertions only, not in a real browser.
- Pre-existing sessions are not backfilled and have no event rows; their totals are unchanged.
- The film notification list is still the newest 50 (pagination is out of scope); the badge now counts beyond it.
- Article notification counts already used a separate unread query and were not changed.
- Analytics and the games-watched dashboard read `watch_duration_seconds` and are unchanged.
