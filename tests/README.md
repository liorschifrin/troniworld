# Regression coverage

Run the README commands from the repository root with Python 3.12 and Node 22 (for isolated JavaScript render tests). Tests use Flask's test client, never the running server. Authentication fixtures place synthetic user IDs in signed sessions; they test authorization, not the shared-password login flow. Admin and leadership are separate roles.

Passing gates cover anonymous login redirects on film pages and JSON 401 on the film comment API; ordinary/leadership point-edit and nonowner-delete denial without mutation; admin point editing; main comment API author/recipient/nonrecipient visibility; hidden-game list filtering; fresh schemas/SQLite foreign keys; temporary upload storage; and configuration isolation guards.

`test_visibility.py` (T03, 137 cases) covers the reachable rows of the [visibility policy matrix](../docs/visibility-policy.md): main film comment visibility (including inherited reply privacy, author-only and malformed `private_to`), hidden-game responses byte-identical to missing-game responses without writes, hidden-game exclusion from lists/my-games/team data/option lists, notification creation and read isolation, admin report counts, and admin-only route access for anonymous, ordinary, leadership, and admin callers. It also verifies the retired `/api/v1/games` route returns 404 for anonymous and admin callers. Q1 option A means leadership/admin flags grant no extra private access. Synthetic tests cover admin author/recipient/nonrecipient and leadership-author combinations, hidden-game ancestors, depth-two notification chains, notification edit history, and unchanged admin writes/watch behavior on visible and hidden games.

Current gates (Python 3.12, Node 22; synthetic in-memory SQLite for the application suites, temporary SQLite files for the T07 migration tests): **1266 passed, 39 skipped** (the opt-in browser tests) with `-m 'not known_failure'`; `-m known_failure` selects nothing (1305 deselected, exit 5) since T09 removed the last expected failure. `test_engagement.py` (T09, 57 cases) covers the watch-time contract, notification read state and unread count, and filtered statistics. `python -m pip check` is clean.

`test_csrf.py` (T05 slice 1, 204 cases) covers all 33 write requests on the 30 state-changing routes. A route-map test fails if a new write route is not listed. Each write is sent the way its real client sends it (form field, `X-CSRFToken` header, or beacon body field) with a server-minted token, and must succeed and change data. Logout must clear the session. Each write is then forged four ways: no token, a wrong token, a valid token from another session, and a victim session with no token. Every forgery must return 403 (JSON error or flashed HTML page), and the snapshot of every table, every upload, and the login state must be unchanged. The file also checks: malformed tokens; that tokens in the query string or a cookie are denied; that a body token is read only for the beacon; that the token rotates at login and register (the old token is denied) and is kept at logout; that GET pages and GET `/logout` work without a token; that 404/405 are unchanged; and that 13 rendered pages carry the session token in `CSRF_TOKEN` and in every POST form. A source scan pins the template inventory (20 fetch writes, 16 POST forms, 1 beacon, 3 jQuery posts) and checks that each one carries the token. The shared `client_for` fixtures put a token in the session and send it on every request, as a page from this site would; only `test_csrf.py` sends requests without a token. Tests use Flask's test client, not a browser. Real cross-site browser behaviour and cookie policy are not exercised.

T12 adds `test_browser.py` (39 cases, marker `browser`) and `browser_support.py`. These are the only tests that run JavaScript in a real browser. They are opt-in: `python -m playwright install chromium`, then `python -m pytest -m browser`; the normal `-m 'not known_failure'` gate lists them as skipped, and they skip with a reason if Chromium cannot start. Playwright is a dev-only dependency (`requirements-dev.txt`, pinned). Each test serves the real pages through Flask's test client (in-memory synthetic database, no socket, no running server) and replaces the YouTube IFrame API with a local stub, so no test needs the network or a real video; every other host is refused (only the Google Fonts stylesheet tries). The matrix is desktop Chromium (1280x800) and Chromium with mobile emulation (390x844, touch); no other browser is claimed. Covered: opening a game, play/pause, posting a comment (keyboard and button, desktop and mobile), marking a notification read (one item and all), the shortcut keys acting once and never while typing in a comment, reply, private-user or video-link field, Space on a focused button, tab order and a visible focus ring across the player controls, accessible names and `aria-pressed`/`aria-expanded` states, the mention list, the notification dropdown and tabs, keyboard roster editing, the admin add-time menu, three YouTube failure modes (script blocked, never answers, embed error) plus Load Video without the API, and the 390 px layout (no sideways scroll, tap-target size, the menu drawer, the dropdown fitting). **Automated vs manual:** everything above is automated in Chromium only. A screen reader, Safari, Firefox, real touch hardware, real YouTube playback and fullscreen were not exercised, and colour contrast was not measured. Mutation checks: removing the editable-text guard fails 4 cases; the pre-T12 templates fail the single-handler, Space-on-button and accessible-name cases (see `docs/orchestration/tasks/T12.md`). The cases that read the player script without a browser (`test_player_template_parts.py`, `test_handler_escaping.py`) are unchanged except one stub gained two no-op DOM methods.
