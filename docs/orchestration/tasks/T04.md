### Decisions (user, 2026-10-25, plus defaults the user did not change)

- Comment length: NO length limit in T04. Request-size protection is T05.
- Reply depth: ONE level only. Replies may target top-level comments only. A reply whose parent is itself a reply is rejected with 400. Same rule for article replies (verify the current article code first; apply the same rule). Existing deeper replies are reported, not changed.
- Timestamps: finite number, 0 ≤ t ≤ 86400 seconds. Reject booleans, NaN, infinity, strings, negatives, out-of-range values. Apply to comment timestamps and point timestamp PATCH.
- Parents: `parent_id` must exist, belong to the same game (or the same post for articles), be a top-level comment, and be visible to the caller under the T03 policy. Otherwise 404 (invisible/missing) or 400 (wrong game / reply-to-reply).
- Points: point references in PATCH and roster/player-sheet updates must belong to the game in the URL; roster players must be valid in the game. Reject otherwise with 404/400 and no writes.
- Errors: JSON only, shape `{"error": "<message>"}`, statuses 400 (validation), 401 (anonymous), 403 (forbidden), 404 (missing or invisible). Never 500 for malformed client input on these routes.
- Booleans and JSON shapes: `private_to` must be a list of strings or null (keep T03 handling for legacy values on read); `is_hidden`/`not_filmed`/similar booleans must be real booleans.
- Output escaping: comment text must not become executable handler text. Where comment text or other stored strings reach an inline `onclick`/handler, pass only validated numeric ids or escape/move the value into a data attribute. Do NOT refactor templates broadly (T11/T12).
- Stored invalid values: report, do not clean up or migrate.
- T09 beacon 500 (`test_string_beacon_does_not_return_server_error`): NOT in T04. Leave its xfail as is.
- No schema change, no migration, no deletion of stored data.
