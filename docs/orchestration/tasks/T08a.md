## Reproduction

`db.session.delete(user)` for a user with `LoginEvent` rows raises `IntegrityError` (the `User.login_events` backref makes SQLAlchemy null `login_events.user_id`, which is NOT NULL). The old admin "Delete" action caught the exception and flashed an error. `tests/test_user_archive.py::test_hard_delete_with_login_records_is_the_reproduced_failure` pins it.

## Decisions

1. **Archive state:** nullable `User.archived_at` (NULL = active). Migration `l7m8n9o0p1q2` (down_revision `k6l7m8n9o0p1`, the T07 head) is one `ADD COLUMN`: additive, no default, no rewrite, no table rebuild, every existing user stays active. Downgrade refuses while any user is archived (dropping the column would reactivate them).
2. **Enforcement point:** `get_current_user()` returns None for an archived user, so every login-required/admin/JSON route treats them as signed out, including sessions issued before archiving. `login` refuses archived users with the same generic failure as an unknown user (logged as `reason=archived_user`).
3. **Reservation:** the existing case-insensitive username lookups in `register` and admin create already match archived rows; admin create now says "archived and reserved". `link_or_create_user_for_player` does not relink an archived user. No code path reassigns a username.
4. **Admin action:** the form action is renamed `delete` -> `archive` (button "Archive", confirm text explains). The old `delete` value is no longer handled (no-op, pinned by test). Admins cannot archive themselves; archiving twice keeps the first timestamp; role toggles on an archived user are refused. Archived rows show an Archived tag and no action buttons. There is no restore action.
5. **Side effects:** archived users are dropped from login suggestions, mention autocomplete, and new `@Everyone` notifications. Existing notifications, tags, and analytics/admin report data are untouched.

## Limitations

No restore, no hard delete, no relational authorship (T08b/Q2): comments still reference the username string, so the reservation is what prevents inheritance. Login suggestions and mention lists are filtered at render time only. Archiving can strand admin access (archive the other admin, then demote yourself), so `toggle_role` now refuses to demote the last *active* admin (CodeRabbit finding, regression test added). Production data was not inspected; whether any deployed username already collides in case is unknown (T08b).
