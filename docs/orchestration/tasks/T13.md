# T13 — Production release and recovery runbook

## Brief (from the manager, 2026-10-26)

- Implementer for roadmap task T13. Branch `task/t13-runbook`, created from `origin/task/t12-browser` (PR #21, stacked on #20, #19, #18, #17). Do not change code from earlier tasks except where T13 needs it.
- Scope: a runbook for running the app as a Flask WSGI app with SQLite and local uploads: host and WSGI choice documented as OPTIONS (not a decision), production configuration, secret handling, dependency checks, backups, health and error reporting, upload persistence, license and publication review, and a rollback procedure.
- Acceptance: (1) debug off and HTTPS/session settings verified by a test that loads the production config and asserts DEBUG off, SESSION_COOKIE_SECURE/HTTPONLY/SAMESITE set, and the secret read from the environment and not a default; (2) database and uploads survive a deploy: documented layout with both outside the code tree, and a test that the upload path is configurable and not inside `flask_app/static` code paths; (3) restore tested: back up a temp database and uploads directory, restore into a clean directory, verify counts (reuse the T07 approach); (4) staging smoke and permission checks: documented checklist (login, view game, admin-only route refuses non-admin) with an automated part on the test client and a clearly marked manual part; (5) rollback rehearsed on a temp database: upgrade a copy, roll back to the previous artifact plus compatible schema or restored snapshot, verify the app still starts against the restored copy; (6) ownership, license and media publication decisions recorded as OPEN.
- Decisions by the user, not re-opened: Q5 stays OPEN (no host, license, team size or recovery-time objective chosen; each is listed as an open decision with options). No deployment; no real host, domain, DNS or secret store; placeholders and environment variables only. Generic WSGI + SQLite + local filesystem runbook; GitHub repository publication is separate from running the service.
- Non-goals: any feature change; visibility, auth, CSRF, import, notification or watch-time logic.
- Rules: venv sourced, no Flask server, no real or production database, no real secrets. Gates plus `coderabbit review --agent --base origin/task/t12-browser` before pushing. Draft PR to `task/t12-browser`. Do not merge.

## What was built

- `docs/runbook.md`: layout (data outside the code tree), host/WSGI options table, production configuration and secrets, dependency checks, backup, restore, upgrade, two rollback paths, smoke checklist (automated and manual parts), health/error reporting, the open Q5 table, a pre-release checklist.
- `flask_app/config.py` and a two-line hook in `flask_app/__init__.py`: the repository had no production configuration (debug/reload and the upload folder were hard-coded, cookies had no Secure/HttpOnly flags). `APP_ENV=production` now applies the production profile and refuses to start on unsafe settings; without it behaviour is unchanged. `UPLOAD_DIR` sets the upload folder.
- `flask_app/uploads.py`: a route `uploaded_file` serves `UPLOAD_FOLDER` at `/static/uploads/<name>` (via `send_from_directory`), because a folder outside `flask_app/static` is otherwise not reachable at the public URL stored in articles. Default behaviour is the same files at the same URLs.
- `tests/test_release.py` (48 cases) and the `README.md`, `ProductSpec.md`, `AGENTS.md`, `tests/README.md` and roadmap updates.

## Changes to earlier-task code (flagged)

1. `flask_app/__init__.py` (base app): upload folder now comes from `apply_config(app)`; the default value is identical.
2. `flask_app/uploads.py` (T05 slice 3): added the `uploaded_file` route. This is the one behavioural addition: serving no longer depends on the static folder. The `nosniff` header, upload validation and naming are untouched.
3. `tests/test_uploads.py::test_nosniff_on_served_uploads` (T05): it faked the static folder; it now writes its probe into `UPLOAD_FOLDER`, the directory that is actually served. Assertions unchanged.

- No health endpoint was added (feature change); `GET /login` is documented as the liveness probe.

## Independent review round (Codex, on 6d14b11): CHANGES REQUIRED, all three points verified and fixed

Consequence: developers and CI now set `APP_ENV=development` (README `.env` example, `tests/conftest.py`, `tests/migration_driver.py`).
